Why it exists

Not more context.
More trustworthy context.

The problem is rarely that an agent cannot read the code. It is that every session must rediscover the same project facts. AI Doc preserves verified understanding together with its chain of evidence back to the source.

01 / TRACE

Every conclusion is traceable

Memories link to a project, Git commit, file, symbol, and line range. Agents can verify the source instead of blindly trusting generated text.

02 / VERSION

Append changes, preserve history

Each revision creates a new immutable version. Design changes and API evolution remain visible, and earlier decisions never disappear behind an update.

03 / RETRIEVE

Exact terms meet semantics

FTS5 captures paths, symbols, and code terms. Local embeddings capture natural-language meaning. Both signals contribute to ranking.

Agent outcomes

Less rediscovery.
More forward progress.

AI Doc changes how an agent begins a task. Instead of rebuilding project understanding from raw files every time, it starts with scoped, versioned knowledge and follows the evidence only where deeper verification is needed.

WITHOUT AI DOC / EVERY SESSION
  1. Search broadly

    Scan files, docs, and symbols to reconstruct the project model.

  2. Repeat old reasoning

    Rediscover decisions and dependencies already understood before.

  3. Trust transient context

    Lose useful findings when the session ends or the context window turns over.

WITH AI DOC / TASK START
  1. Retrieve the relevant memory

    Search by intent, API term, path, or symbol within an explicit project scope.

  2. Verify the evidence

    Follow exact code references and Git context instead of accepting an unsupported summary.

  3. Continue from prior work

    Use immutable history to understand what changed, then append the newly verified state.

01 / FOCUS

Smaller context footprint

02 / SPEED

Less repeated exploration

03 / SAFETY

More defensible changes

Ground plans and edits in code references, commit context, and append-only version history.

04 / CONTINUITY

Durable agent handoffs

Leave structured project knowledge for the next agent or session instead of a disposable chat transcript.

Memory lifecycle

From source facts
to the next action.

Writing is not the finish line. A memory is validated, versioned, indexed, and retrieved, then verified by an agent through its code references before the next change.

STEP 02

STEP 03

Version

STEP 04

STEP 05

Retrieve across sessions and follow references to the implementation.

Data model

Minimal entities.
A complete evidence chain.

SQLite provides authoritative storage and full-text indexing. Projects define isolation, memories have stable identities, versions are append-only, and code references connect natural-language conclusions to exact implementations.

Delivery path

Then expand the boundary.

Complexity is introduced only when real needs demand it: first complete local reporting, revision, retrieval, and maintenance, then add remote sharing, change awareness, and quality governance.
